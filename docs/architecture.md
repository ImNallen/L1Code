# L1Code architecture

## Problem

L1Code is a small, fast IDE for quick edits and testing, built on Tauri 2 and React. The window has three full-height columns and no title bar. The left column is the file tree with a name filter on top. The middle column is a tabbed code editor. The right column holds tools: Preview, PR, Terminal, and Changes. Changes also stages and commits.

Rendering is the easy part. The hard part is keeping one truth for three facts that several actors change: the draft, the disk, and git. Our save, the user's terminal, and other programs all write to disk.

Two libraries constrain the shape:

- `@pierre/trees` takes the whole path list eagerly and keeps its own model. Large repos therefore need a fast walk that respects `.gitignore`, followed by small deltas.
- `@pierre/diffs` renders patches well. It also ships an editor whose draft lives in the component.

## Usage

### Add a right-panel tool

1. Create `src/slices/problems/` with `index.ts` and `ProblemsTool.tsx`.
2. Export the slice definition from `index.ts`:

   ```ts
   export const slice = defineRightTool({
     id: "problems",
     title: "Problems",
     icon: AlertTriangle,
     shortcut: "Mod+Shift+M",
     component: lazy(() => import("./ProblemsTool")),
   });
   ```

3. Add `problems` to the `right` array in `src/slices/manifest.ts`.

Everything else derives from that entry: the tab, its order, its shortcut, and the persisted layout id. If the tool needs a backend, add `src-tauri/src/problems.rs` with `#[tauri::command] #[specta::specta]` functions and add them to the single `commands![]` list in `lib.rs`. The TypeScript bindings regenerate from that list.

### Add a left view

Use `defineLeftView({...})` and add the slice to `left: [...]` in the manifest. The left column gains a collapsible section.

### Open and save a file

```ts
import { editor } from "@/slices/editor";

await editor.open("src/main.rs", { line: 42 }); // focuses the existing tab, or reads from disk
await editor.save();                             // active doc; no-op when clean
```

### Real call sites

```ts
// explorer/ExplorerView.tsx: Enter in the filter opens the first match
if (path) void editor.open(path);

// terminal/sessions.ts: a file:line link in terminal output
linkProvider -> editor.open(path, { line })
```

## Shape

**Slices and one manifest** (base: candidate 3). Each feature is one folder under `src/slices/<id>/`. Only its `index.ts` may be imported from outside the folder, and ESLint fails the build otherwise. `index.ts` exports `slice`, the definition the manifest consumes, and at most one owner API object, such as `editor`, `scm`, `changes`, `explorer`, or `terminal`. Cross-slice calls go through owner APIs. They never go through an event bus. `src/slices/manifest.ts` is the only list of features. The shell derives tabs, order, shortcuts, and valid persisted ids from it.

**State.** Each slice owns its stores, built with `core/store.ts`, a 30-line `useSyncExternalStore` wrapper. The writable handle is module-private. Other modules get a read-only store or call the owner API. No global store means no second writer can exist (per separate-before-serializing-shared-state).

**Documents** (grafted from candidate 2). The editor slice owns every open document. Each `Doc` holds:

- `state`, a CodeMirror 6 `EditorState`. It is the only copy of the draft, including its undo history.
- `baseline`, the text and content hash we last agreed with disk on.
- `disk`, which is `synced`, `changed`, or `deleted`.

Dirty is derived: `!state.doc.eq(baseline.text)`. Undo back to the saved text reads as clean. All disk I/O for a path (open, save, reconcile) runs through one per-path promise queue. `decideReconcile(doc, read)` is a pure decision table. Saves are compare-and-swap writes against `baseline.hash`, so we never overwrite a change we haven't seen.

**Rust holds the workspace, not the documents.** `workspace_open(path, onFs)` canonicalizes the root and stores it with the watcher and the PTY table. Every other command takes `RelPath` arguments, which are validated on deserialize. The webview can't address files outside the root. The command list in `lib.rs` is the single source for `src/core/bindings.gen.ts`, generated by tauri-specta. Only `src/core/ipc.ts` and `slices/*/ipc.ts` may import the bindings. Those files convert wire types into domain types.

**Streams.** Every stream uses a per-call `Channel`, never a global `emit`. The streams are watcher batches and PTY output. The one exception is the single-instance "open path" event from a second `l1code <path>` launch.

**Editor engine: CodeMirror 6.** It is mature for daily typing: IME, multi-cursor, multi-MB files, and incremental parsing. Its `EditorState` is a value the editor slice can own outright. The `@pierre/diffs` editor would make the component the owner of the draft ("the editor takes ownership", "don't feed onEditChange back"). That splits ownership of the one fact that matters most. `@pierre/diffs` renders the Changes panel and the conflict compare view. The engine is hidden behind the editor slice, so it can be swapped later.

### Hard cases

- **Dirty file changes on disk.** The watcher batch reaches `editor.reconcile(path)`, which is queued behind any save. It reads from disk and calls `decideReconcile`:
  - Same hash: no-op.
  - Clean doc: reload as one undoable transaction.
  - Disk now equals the draft: adopt the baseline.
  - Otherwise: `disk = changed`, and a banner offers Compare, Keep mine, and Take disk.
- **Our own write echoes from the watcher.** The reconcile waits in the queue behind the save. The save sets the new baseline hash, so the reconcile sees an equal hash and does nothing. There is no timing window and no ignore flag.
- **100k files.** Rust walks with `ignore::WalkParallel` and returns one newline-joined byte buffer, with directories ending in `/`. The explorer owns a path set and the `@pierre/trees` model as a projection of it. Watcher batches become `model.batch(ops)`. A batch of more than 2,000 changes, an overflow, or a `.gitignore` change re-lists.
- **PTY lifetime.** Rust owns each PTY for the life of the workspace. A reader thread drains output into a 1 MiB ring addressed by byte sequence number. A hidden tab keeps its xterm in the terminal slice's registry; the instance is re-parented on show, and 0x0 resizes are ignored. On a window reload, the dead channel is dropped, the new page lists the sessions, and it re-attaches from the ring.
- **Git refresh.** There is one entry point, `scm.refresh()`. It is single-flight, debounced at 150 ms, and runs again if called during a run. The triggers are:
  - A save.
  - A watcher batch with `gitMeta` (`HEAD`, `index`, or `refs` changed). This covers a terminal `git commit` and a branch switch.
  - Any worktree change.
  - Window focus.

  `git status` runs with `GIT_OPTIONAL_LOCKS=0` so it cannot retrigger itself through the watcher.

### Deliberately not done in v1

- LSP.
- Multi-root or multi-window workspaces.
- Hot exit. Closing with dirty docs prompts instead.
- Editing inside Changes.
- vt100 screen replay.
- A command palette.
- Porting the trees sort to Rust before it is measured.

## Synthesis decision

Three runners produced structurally different candidates:

1. A Rust-owned core with a CodeMirror collab authority.
2. A frontend-owned store with stateless Rust.
3. Vertical slices with one manifest, using the `@pierre/diffs` editor.

The cross-judge picked candidate 3 as the base and scored it 26 against 23 and 22. The orchestrator initially leaned toward candidate 2 for its v1 cost. The two converged on candidate 3's skeleton with candidate 2's document model.

- **Base, from candidate 3:** the manifest, slice folders with an `index.ts` entry, owner APIs instead of a bus, Rust holding the root, the PTY ring with re-attach, and the per-slice `useSyncExternalStore` store.
- **Grafted from candidate 2:** the CM6 `EditorState` as the only draft, derived dirty, the pure `decideReconcile`, the per-path queue, compare-and-swap writes, the hidden-terminal resize guard, `GIT_OPTIONAL_LOCKS=0`, and raw bytes from `fs_list`.
- **Grafted from candidate 1:** a stat check before save, and quick open over the path index.
- **Added from the judge's "all missed" list:** `l1code <path>` with single-instance handoff (opening a file opens its parent folder), Preview's "open in browser" fallback, and `file:line` links in the terminal.
- **Rejected from candidate 3:**
  - The `@pierre/diffs` editor, because of split draft ownership and an unverified injection assumption.
  - The Rust `known` disk-version map, which duplicates `baseline`.
  - The command palette and focused-scope commands.
  - The custom lint rule.
  - The `register!` macro, because one `commands![]` list is enough.
- **Rejected from candidate 1:**
  - The core thread, the collab protocol, and keystroke IPC. They cost weeks for a quick-edit tool.
  - vt100 replay, deferred.
- **Rejected from candidate 2:** passing `root` from the webview on every call, killing PTYs on reload, and a global store with a runtime `claimWriter` check.

## Tradeoffs accepted

- We accept two highlighters, Lezer in the editor and Shiki in diffs, in exchange for an editor whose state we own.
- We accept that a window reload loses drafts and undo history, but not terminals, in exchange for no Rust-side buffers.
- We accept a JS sort of the path list (about 100 ms at 100k paths) until it is measured, in exchange for not hand-porting the trees comparator.
- We accept that Changes shows HEAD versus disk, not the draft, in exchange for exactly one buffer owner.
- We accept raw replay of the terminal ring, which can garble full-screen apps after a reload, in exchange for not shipping a vt100 model.

- We accept that background git runs without the repository's fsmonitor, filter drivers, and textconv, in exchange for opening an untrusted folder never running a program its `.git/config` names. Files tracked by Git LFS can therefore show as modified, or diff against their pointer, in Changes. Stage and commit still use normal git.

## Alternatives considered

- **Rust-owned documents (candidate 1).** Its interface is deepest: lossless reload and search over drafts. It needs a collab protocol and per-keystroke IPC, which is too much machinery for v1.
- **Global frontend store (candidate 2).** It is the smallest to build. Ownership is enforced at runtime instead of by module scope, and the webview addresses arbitrary roots.
- **The `@pierre/diffs` editor (candidate 3).** It needs zero extra dependencies and gives one highlighter. The component owns the draft, so the editor slice would mirror it.

## Open questions and risks

- Does `resetPaths` with 100k prepared paths stay under about 150 ms? If not, should the trees sort move to Rust?
- Does Tauri's raw `Channel` payload arrive as an `ArrayBuffer` in WKWebView? If not, PTY frames fall back to base64.
- tauri-specta is pinned to `2.0.0-rc.25`. Is a release candidate acceptable, or should we use `ts-rs` with hand-written invoke wrappers?
- `@pierre/diffs` is pinned to `1.5.2`. Version `1.6.0` was published against an unreleased `@pierre/theming`, which supports a `fallbackLoader`; the published `1.0.1` does not. As a result, the default theme never loads on the main thread and every diff renders empty. Unpin when a matching `@pierre/theming` ships.
- Should hot exit, meaning drafts that survive quit, come before v1.1?
